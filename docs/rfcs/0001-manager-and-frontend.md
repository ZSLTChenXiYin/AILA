# RFC 0001 · 管理器与编译器前端的形态

> **编号**：0001 · **类型**：RFC · **状态**：已被 [rfcs/0003](0003-go-rewrite.md) 取代（本文保留历史决策记录）
>
> **重建说明**：G4 收尾时本文档被一次误操作清空，此处依据会话内可见的原文片段 + 决策要点重建。
> 结构、结论与证据链与原版一致；个别措辞可能不同。**当前实现见 [rfcs/0003](0003-go-rewrite.md)。**

## 1. 要回答的问题

AILA 需要的命令行工具至少有两个角色：**管理器**（工程发现、清单、工具链供给、构建编排）与
**编译器前端**（词法 → 语法 → 语义 → LLVM IR 文本）。本文只回答两件事：

1. 这两个角色**用什么语言实现**（以及为什么）；
2. LLVM 后端与 C 解析通道**怎么接**（在没有 clang / 没有 LLVM 开发库的机器上也能跑起来）。

语言设计与语义细节不在本文范围内（见 [`designs/0001`](../designs/0001-language-spec.md)）。

## 2. 约束（当时的机器现实）

| 事实 | 后果 |
|---|---|
| 机器上**没有 Rust、没有 clang、没有 LLVM**；只有 Python 3.11 与 GCC 14.2（w64devkit）、Node | 前端实现语言、IR 落地方式、C 解析通道全部受此约束 |
| 有网络（可安装 Python 包） | 可用 `llvmlite`（自带 LLVM 后端）作为「内嵌 LLVM」的 M1 载体 |
| 目标用户是嵌入式开发者，发布形态要求「解压即用」 | 工具链必须能随包分发；管理器不能要求用户先去装一堆系统依赖 |
| 项目要开源到 GitHub 并分发 | 构建脚本要能被 CI 复现，不能依赖作者本机的偶然状态 |

## 3. 方案对比（前端实现语言）

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| **A. Python 3.11（自研前端，零第三方依赖）** | 环境已有、`git clone` 即跑、诊断文字与文档同源、可读性对 AI/人共读友好（对齐 [designs/0001 §1.1 L3](../designs/0001-language-spec.md)） | 速度慢、分发需要 Python 运行时 | **采纳** |
| B. Rust | 性能最好、单文件分发 | 本机没有 Rust；迭代期编译等待会直接吃掉探索速度 | 否决（M1 阶段） |
| C. C/C++ | 与 LLVM 生态贴合 | 手写前端在 C 里迭代成本过高，内存安全全靠自律 | 否决 |
| D. Go | 单文件分发、编译快、标准库够用 | 本机没有 Go；原型期要先把语言设计跑通 | **推迟**（见 §6 / [rfcs/0003](0003-go-rewrite.md)） |

> 结论的代价（登记）：Python 的编译速度比 Rust 慢一个量级，大工程（万行级）单次全量前端预计 1–3 s。缓解 = 模块级增量缓存（[specs/0001 §7](../specs/0001-manager-cli.md)）。

## 4. 方案对比（后端与 C 解析通道）

| 方案 | 说明 | 结论 |
|---|---|---|
| 直接生成目标代码（LLVM C++ API / 自研后端） | 需要 LLVM 开发库或写后端，M1 成本过高 | 否决 |
| **生成 LLVM IR 文本 + `llc`/`clang` 落目标文件** | IR 文本可审计、可 diff、可做黄金快照；后端可替换（随包 llc / 系统 llc / llvmlite） | **采纳** |
| C 转译（AILA → C → 编译） | 借用 C 的优化器最快 | 否决：区域语义 / 陷阱语义很难在 C 里表达准确，且会把「陷阱」变成 UB |

C 解析通道（`import ch`）：首选 `clang -ast-dump=json`；没有 clang 时用内置 C 声明子集解析器兜底，
并**逐条打印边界提示**（绝不静默降级）。两档共用同一套类型映射与命名规范，AILA 侧代码不感知档位。

## 5. 决策表

| 编号 | 决策 | 理由 |
|---|---|---|
| D1 | 前端自研（不借 C 编译器做语法层） | 语言有大量独有概念（`region` / `@` 子句 / `T?` / `T ! E`），改造成本高于自研 |
| D2 | 前端 Python、后端 LLVM IR 文本、三级 LLVM 供给 | 环境现实 + 可审计 + 可替换 |
| D3 | 工具链**随包分发**为默认路径，`system:` 只在清单显式要求时启用 | 「解压即用」是产品约束；隐式回退会让「能编」这句话不可信 |
| D4 | 错误码表与 target 表放 `share/aila/data/*.json`，实现只读这一份 | 重写/多实现期最怕两套码表漂移，从根上消掉 |
| D5 | 诊断格式 `error[E3201]: 消息` + 位置 + 帮助 + 设计稿出处 | 错误信息是语言体验的一部分，不是实现细节 |

## 6. 风险登记

| 风险 | 缓解 |
|---|---|
| Python 性能 | 模块级增量缓存；前端纯单线程；不做 SSA 优化 |
| 分发需要 Python 运行时 | M1 先接受；**G4 换成 Go 单文件**（[rfcs/0003](0003-go-rewrite.md)） |
| 两套实现漂移 | 黄金语料 + 逐字节快照判据（token / AST / 布局 / 签名 / IR） |
| 生成的 IR 跨 LLVM 版本不稳定 | 只用保守指令与 `*.with.overflow` intrinsic；LLVM 版本带 `18..23`，带外给 `W8012` |

## 7. 交付与验收（M1）

1. `aila new / doctor / check / build / run / toolchain / target / explain` 可用；
2. 六个示例（hello / control / region / struct / result / cinterop）端到端跑出预期输出；
3. IR 与目标文件可由随包 llc/clang 或系统后端产出，缺后端时诊断给可执行命令；
4. 说明文档与代码同步（本文 + specs + plans）；
5. `tests/` 全绿（`python -m unittest discover`）。
