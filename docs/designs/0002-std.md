# DESIGN 0002：标准库设计与分层

> **编号**：0002 · **类型**：DESIGN · **状态**：已共识（M1 重构依据）
> **上游**：[designs/0001](0001-language-spec.md)（语言权威）、[designs/0001 §12.3/§13](0001-language-spec.md)（运行时分工）
> **同批**：[specs/0002](../specs/0002-compiler-frontend.md)（前端实现契约）

标准库的设计参考了三方成熟经验，各取所长：

| 来源 | 采纳的点 | 不采纳的点 |
|---|---|---|
| Rust `core`/`alloc`/`std` 三层 | 逻辑核心零 OS 依赖、可裸机编译；错误即值 | trait 动态分发（M1 无 interface） |
| Go `io.Writer` 小接口 | 单方法接口 + fmt 引擎写进 Writer；itab 的 vtable 本质 | 反射与运行时类型信息 |
| C freestanding + syscall 桩 | OS 边界收窄为最小 C 垫片；其余全可移植代码 | printf 家族（解析格式串的运行时开销与不可静态校验） |

---

## 1. 纯度三线

std 里每一行代码按「谁必须实现它」分三条线，边界不模糊：

| 线 | 内容 | 实现语言 | 理由 |
|---|---|---|---|
| ① 纯逻辑 | 格式化引擎、缓冲区算法、UTF-8、整数数学、各域错误词表 | **100% AILA**，零 `#[c]`、零 OS 依赖 | 可移植、可静态检查、跟随语言演进 |
| ② 语言 ABI | region 四件套（`aila_rt_region_enter/alloc/leave/static_region`）、`aila_rt_trap` | C（语言运行时的一部分） | 与 codegen 的调用约定强耦合，不是「库」 |
| ③ 平台垫片 | `aila_rt_write` / `aila_rt_flush`（及将来的 clock 等） | C，每平台 ~200 行纯数据搬运 | OS/外设边界各平台差异大，AILA 无法表达 |

判定法：一段代码如果换一个平台不需要重写，它属于①；如果它只是把字节从 AILA 搬到平台 API，属于③；其余属于②。

## 2. io 抽象：vtable Writer

M1 没有 interface，但函数指针已经语义齐备。Writer 采用 **vtable struct** 形态——这正是 Go `io.Writer` 小接口在运行时的真实样子（itab = 方法表 + 数据指针）：

```aila
// std.io
public struct Writer {
    write: ([Unsafe]?, [U8], USize) -> USize,   // 槽位：写入 bytes 前 n 字节，返回实际写入数
    ctx:   [Unsafe]?,                            // 后端自有状态（stdout 无状态 → None）
};
```

- **fmt 引擎写进 Writer**：`put_u64` / `put_f64` / `put_text` 等方法把 `std.core` 的缓冲区算法结果交给 `self.write` 槽位。引擎不知道后端是什么。
- **后端即实例**：stdout、UART、内存缓冲都按同一签名提供 write 函数 + ctx，构造一个 `Writer` 值即可接入。换后端 = 换一个 struct 值，无任何分发开关。
- **平滑升级**：语言将来加 interface 时，`Writer` 的方法集原样成为接口方法集，vtable 换成编译器生成的 itab，用户代码不动。

## 3. 错误值：每域瘦 enum + 载荷

错误模型是「每域一个瘦 enum、载荷进字段、走语言级 `T!E` 通道、错误值零分配」：

```aila
// std.core —— io 域的错误词表
public enum IoErr {
    Closed;
    NoSpace { need: USize };
    Timeout;
};
```

- 错误 enum 是普通带载荷 enum：无堆、无装箱，match 解构即取载荷；
- M1 的 stdout 后端写失败无可恢复语义（UART 忽略、宿主 write 由 trap 兜底），因此 **M1 的 write 槽位暂不携带 `!IoErr`**，返回写入字节数；接口化（M2）时升级为 `-> USize ! IoErr`，`enum` 词表现在就位；
- `print` 家族（`print` / `println` / `printf`）**遇错静默吞**（C printf / Go fmt.Println 同理）；要精确处理写入结果的调用方直接使用 Writer 方法（返回值就是写入数），M2 错误通道就位后用 `?` 传播。

## 4. print 形态

**纯库原则（2026-10-23 共识）**：std 里所有函数都是普通 AILA 函数，编译器零特例。打印格式化不靠编译器内建展开、不等 interface/any——异构实参走 **FmtVal 封闭联合**（AILA 的带载荷 enum 本身就是 tagged union）。

| 形态 | 状态 | 说明 |
|---|---|---|
| `print / println / printf` 三函数 | **当前唯一便利层** | 遇错静默吞；`print`/`println` 逐实参直接连接（无分隔符），`println` 末尾换行并冲洗 |
| `Writer.put_*()` 方法族 | **引擎层** | fmt 引擎本体；三函数与格式符分派都落在它上面 |
| `print_x()` 旧函数族 | **已删除** | 被 print 家族取代（2026-10-23） |
| 编译器内建展开（Rust `format_args!` 式） | **否决** | 违反纯库原则 |

```aila
// std.io —— 封闭联合：printf 只支持基础类型，tag 分派编译成 switch，无运行时反射
public enum FmtVal {
    I { v: I64 };    // 有符号整数（%d）
    U { v: U64 };    // 无符号整数（%u）
    F { v: F64 };    // 浮点（%f）
    B { v: Bool };   // 布尔（%b）
    C { v: C32 };    // 字符（%c）
    T { v: Text };   // 文本（%s）
};

print("a = ", FmtVal.I { v: 42 }, "\n");
println("n = ", FmtVal.I { v: 42 });                    // print + 换行冲洗
printf("n=%d f=%f s=%s%%\n", FmtVal.I { v: 1 }, FmtVal.F { v: 1.5 }, FmtVal.T { v: "x" });
```

- **规范宽收录**：FmtVal 只收规范宽度（I64/U64/F64），窄类型由调用方 `as` 拓宽——零隐式转换铁律的一致延伸；
- **格式符集**：`%d %u %f %b %c %s %%`，最小集（无宽/精度/长度修饰）；格式符与实参 tag 错配 = 编程错误，`trap` 终止（fail fast，同下标越界性质）；实参不足时下标越界 trap 自然兜住；
- **M2 演进**：interface/any 落地后可提供 `...any` 开放集版本（或并存），FmtVal 语义原样保留。

## 5. 分层落位

模块 = 扁平文件（`stdlib/<名>.aila`，路径即身份 `std.<名>`）：

| 层 | 模块 | 内容 | 依赖 |
|---|---|---|---|
| 逻辑核心 | `std.core` | fill 引擎（u64/i64/f64 十进制）、UTF-8 编码、整数数学（`std.math` 并行保留）、各域 Err enum | 无 |
| io | `std.io` | vtable Writer、stdout 后端、`put_*` 引擎方法、`print`/`println`/`printf` 便利层 | `std.core` |
| 容器（M2+） | `std.alloc` | region 容器 List / TextBuf / Map | `std.core` |
| 平台垫片 | `runtime/<家族>/`（C） | aila_rt 原语：write/flush（③）、region 四件套 + trap（②） | — |

依赖方向恒定向下：`std.io → std.core`，运行时 C 只被 `#[c]` 绑定引用，永不反向。`std.math` 维持独立模块名以保 import 兼容，其定位（显式回绕 / 钳制出口，designs/0001 §13.5）不变。

## 6. 变参：`...T` 视图化（2026-10-23 共识）

参考 Go 的成熟设计（`args ...T` 体内即 `[]T` 切片），映射到 AILA 的视图模型：

```aila
func sum(base: I64, rest: ...I64) -> I64 {
    var s: I64 = base;
    for v in rest { s = s + v; }   // rest 的类型就是 [I64] 只读视图
    return s;
}

sum(1, 2, 3, 4)   // 调用点：实参数量编译期已知 → 栈上打包，传视图
```

| 决策 | 内容 |
|---|---|
| 语法 | `rest: ...I64`——`...` 是类型构造器，仅允许出现在**参数列表末位**；体内 `rest` 归一化为 `[I64]` 只读视图，for-in / `len` / 下标 / 传参全部复用视图机制，零新语法 |
| 与 C 变参正交 | `#[c]` extern 的无名 `...` 保持 C 语义（调用约定直传，declare 带 `(...)`）；AILA 原生变参必须有名字与元素类型（`name: ...T`），两套不混 |
| 调用点打包 | 栈上 alloca `[N x T]` 逐个 store，传 `{ptr, N}` 视图——零堆分配、零 region 要求，嵌入式友好 |
| 生命周期 | 变参视图是**调用期借用**，体内不得把它存出/返回；视图只读 + 无堆存储的既有规则兜底，M1 不新增检查 |
| 范围限制 | fnptr 类型不携带 `...`；不做调用点切片展开（`f(xs...)`）——需要时 for 循环显式拼 |
